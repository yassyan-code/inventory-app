# 運用（第22回）— オンボーディング・管理画面・サポート

「作って売る」の後ろの「支え続ける」側。監視は [SLO](slo.md)、障害対応は [incident-runbook](incident-runbook.md)。

## オンボーディング（初回ガイド）

- `src/components/OnboardingGuide.jsx`。「スキャン登録」タブの先頭に出る。
- 表示条件: そのチームの（非表示でない）商品が **0 件** かつ、ユーザーが手動で閉じていない。
- 「最初の成功 = 最初の商品を1件登録」。1件でも登録されると `countProducts()` が 1 以上を返し、ガイドは自動で消える。
- 手動で閉じた場合は `localStorage['onboard_dismissed_<teamId>']='1'` に記録し、そのチーム・その端末では再表示しない。

## 運営用の管理画面

- タブ「運営」。`ADMIN_EMAILS`（`.env` / Vercel、カンマ区切り）に載っているメールのユーザーだけに表示される。
- 判定は **サーバー側**（`api/admin-overview.js` が Bearer トークンからメールを確認）。フロントはタブの出し分けだけで、データは API を通らないと取れない。
- 全テナント横断の集計は `service_role` で行う（RLS 貫通）。取得内容:
  - サマリ: テナント数 / Pro 数 / 支払い遅延 / 解約予定 / 推定 MRR（Pro 数 × ¥1,980）
  - テナント一覧: 名前・プラン・状態・人数・商品数・今月の AI チャット回数・作成日
  - 最近の監査ログ 20 件
- **本番の許可メール設定**: Vercel の環境変数に `ADMIN_EMAILS=あなたの本番ログインメール` を設定。ローカルは `.env`。

## サポートの入口

- フッターの「サポートに問い合わせる」= `mailto:`（`src/App.jsx` の `SUPPORT_EMAIL` を本番の窓口に置き換える）。
- 「使い方」= README へのリンク。
