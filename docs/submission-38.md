### 見つかった危ないところ と 対処

**1. `.env.bak` がローカルに残っていた（対処済み）**
- 課金機能を作る前の古いスナップショット。固有情報はなかったが、`ANTHROPIC_API_KEY` が現行 `.env` と一致＝今も有効な本物のキーを含んでいた。
- git には未追跡だったが、「バックアップ」という名の置き忘れファイルに有効なキーが入っている状態。
- 対処：`.env.bak` を削除した。（理想は Claude API キーのローテーション＝新キー発行。任意）

**2. `.gitignore` の順序バグ（対処済み）**
- 末尾の `.env*` が `!.env.example`（追跡許可）を打ち消していて、チーム共有用の雛形 `.env.example`（値は空）が git に載らない状態だった。
- 漏れ方向ではなく安全側のバグ。対処：末尾の `.env*` 行を削除。`.env` `.env.local` `.env.bak` は無視、`.env.example` は追跡可、を確認。

### 覚えておく区別
`VITE_` 付きの変数（`VITE_SUPABASE_ANON_KEY` 等）はビルド時にブラウザ用 JS へ埋め込まれる＝公開される。anon キーは RLS で守る前提なので公開して正しい。「`.env` に入れた＝秘密」ではなく、`VITE_` は公開・`VITE_` なしはサーバー限定、と理解する。

## 2. 秘密の正しい置き場と、GitHub に上げてはいけない理由

**「.env / 環境変数に置く」の意味**
- コードには `process.env.STRIPE_SECRET_KEY` という名前だけ書く。
- 実際の値はコードの外に置く：ローカル＝`.env` ファイル（`.gitignore` で除外）／本番＝Vercel・Railway の環境変数欄。
- こうすると、値を差し替えても・漏らしても、公開してよいコードと秘密の値が完全に分離する。

**GitHub に秘密を上げてはいけない理由**

| 理由 | 中身 |
|---|---|
| 消しても消えない | 後のコミットで削除しても git の履歴に永久に残る。`git log -p` で掘り出せる |
| 自動収集されている | 公開リポジトリは bot が常時スキャン。push から数分〜数十秒でキーが悪用された事例が多数 |
| 被害が青天井 | Stripe 秘密鍵なら決済を作られる、`SERVICE_ROLE` なら RLS を無視して全テナントの DB を読み書きされる、Claude キーなら課金を焼かれる |
| 巻き戻せない | 漏れたキーは「無効化して新しいキーを発行」しか手がない |

定石：`.gitignore` で `.env` を除外 → `.env.example`（値は空）だけ共有。

## 3. SQL インジェクション と XSS（たとえと、自分のアプリの注意点）

**SQL インジェクション＝「注文用紙」の空欄に命令を書き込まれる**
検索欄に `'; DROP TABLE products; --` のような文字を入れられ、それが SQL 文の一部として実行されてしまう攻撃。
- 防ぎ方：入力を「値」として別枠で渡す（パラメータ化）。文字列で SQL を組み立てない。
- 自分のアプリ：`supabase-js`（`.eq()` `.is()` `.order()`）と `.rpc()` のみ。生 SQL の文字列連結ゼロ。今は安全。今後 `api/` で生 SQL を書くときだけ必ずプレースホルダを使う。

**XSS＝「掲示板」に貼り紙のふりした仕掛けを貼られる**
入力欄に `<script>盗む処理</script>` を保存され、それが他のユーザーの画面でそのまま実行されてしまう攻撃。ログイン中のトークン（JWT）を盗まれ、なりすましされる。
- 防ぎ方：ユーザー入力を画面に出すとき HTML として解釈させない（エスケープ）。
- 自分のアプリ：React が `{値}` を自動でエスケープ。`dangerouslySetInnerHTML` も `innerHTML` も未使用。今は安全。注意点は「将来 `dangerouslySetInnerHTML` を使いたくなったら入力元を疑う」。商品名・カテゴリ名などユーザー入力を innerHTML で描画しない。

## 4. 一番ヒヤッとした点

GitHub に一度上げた秘密は、後のコミットで消しても履歴に永久に残ること。しかも公開リポジトリは bot が常時スキャンしていて、push から数分で悪用され得る。「消せばいい」が通じないのが怖かった。加えて、自分の環境にも `.env.bak` という形で有効な Claude キーが置き忘れられていた。
