## ① やることをチケットに割る

### 見積りポイントの決め方

- ポイントは**時間ではなく「重さの相対比較」**。基準になる小さなチケットを1つ決め、それと比べる
- 数字は 1・2・3・5・8 だけ使う(細かい差を争わない)
- **8は大きすぎる印**。8が出たら、割り直す
- 基準(1ポイント)= 「未使用ファイル `icons.svg` を消して、ビルドが通ることを確認する」くらいの重さ

## ② スプリントを組む(1週間)

**スプリントゴール(1文):** 「入出庫の履歴を、画面で見られるようにする」

### 入れすぎない考え方

1. **容量を先に決める。** 1週間に使える時間から、仮の容量を **8ポイント** とする(例)。まだ実績が無いので、最初は当てずっぽうでよい。1回回して、実績で直す
2. **容量いっぱいは入れない。** 想定外(不具合・割り込み・デプロイの確認)に備えて、**容量の7〜8割(= 6ポイント)** にする(第84課題のバッファと同じ考え)
3. **ゴールに効くものだけ入れる。** 「ついでにこれも」を入れない。ゴールと関係ないものは次のスプリント
4. **終わりの定義を決める。** 「動いた」でなく、完成の条件(上の表)を全部満たし、テストが通り、マージして本番デプロイが成功したら完了
5. **途中で足さない。** 足すなら、同じ重さの何かを外す

## ③ ふりかえりの型

### 型: 良かった / 改善 / 次やる

| 見出し | 書くこと | 注意 |
|---|---|---|
| **良かった**(続けたいこと) | うまくいったこと・効いたこと | 人でなく、**やり方**を書く |
| **改善**(困ったこと) | 詰まったこと・ムダだったこと・予想とずれたこと | 責める言葉にしない。事実で書く |
| **次やる**(アクション) | 次のスプリントで**実際に試す**こと。**1〜2個だけ** | 誰が・いつまでに・どうなれば成功か、まで決める |

### 見る数字(1人でも)

- **計画したポイント** と **終わったポイント**(これがベロシティ。次の容量の根拠になる)
- 見積りより**大きくずれた**チケットと、その理由(第84課題の「読み違えた作業」と同じ見方)

### 問いかけ(詰まったとき)

- 予定どおり進まなかったのは、見積りか、割り込みか、前提の見落としか
- 最初に決めた「完成の条件」は、足りていたか・多すぎたか
- 次のスプリントで、**1つだけ**変えるなら何か
