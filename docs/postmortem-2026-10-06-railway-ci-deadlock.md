# ポストモーテム: Railway本番デプロイが3回連続でスキップされた（CI待ちの循環）

| 項目 | 内容 |
|---|---|
| 日付 | 2026-10-03〜2026-10-06 |
| 種別 | 実際の障害（設定の不整合）。利用者への実害なし |
| 環境 | Railway 本番（production）。staging は影響なし |
| 影響 | PR #31・#32・#33 の本番デプロイが `SKIPPED`。本番は #30（2026-10-02）のまま。3件ともドキュメント／CI設定のみの変更で、アプリの挙動に差はなかった |
| 検知〜復旧 | 検知: #33 マージ後の `Verify Railway Deploy` 失敗（2026-10-06）。復旧: 同日、CI待ちをオフにして最新コミットを再デプロイ |

## 何が起きたか

#33 をマージしたところ、CI は成功したのに `Verify Railway Deploy` が failure になった。
Railway を見ると、staging は約30秒で SUCCESS、本番は `WAITING` のまま約7分後に `SKIPPED` になっていた。
過去を遡ると、#31・#32 も同じ経過（`WAITING` → 約7分後に `SKIPPED`）で、本番は 2026-10-02 の #30 以降デプロイされていなかった。

## なぜ起きたか

- 直接原因: **Railway の「Wait for CI」(`checkSuites: true`) と `Verify Railway Deploy` が、お互いの完了を待つ循環になっていた。**
  - Railway 本番は、そのコミットの全 GitHub ワークフローが終わるまでデプロイを待つ。
  - `Verify Railway Deploy`（第57課題で追加）は push で起動し、本番デプロイの完了を最大400秒ポーリングする。
  - つまり Railway は verify の終了を待ち、verify は Railway の完了を待っていた。400秒で verify がタイムアウトして failure になり、その直後に Railway が本番を `SKIPPED` にした（07:50:16 → 07:50:20）。
- 根拠: 3件とも待ち時間が約7分で一致。staging には CI待ちがなく、同じコミットが即 SUCCESS。
- 根本原因（仕組みの穴）:
  1. **第57課題の監視ワークフローを足したとき、既存の「Wait for CI」との相互作用を確認していなかった。**
  2. **本番が `SKIPPED` でも、アプリは動き続けるため気づきにくい。** 気づけたのは verify が failure になったから。
  3. PR #32 の修正は `SKIPPED` の判定だけに対応しており、`WAITING` が400秒を超えるケースは対象外だった。

## どう直したか

1. Railway ダッシュボードで本番の「Wait for CI」をオフにした（`checkSuites: false`。MCP からは切り替えられず、手動で設定）。
2. 本番の `5b94291`（#33）を「Deploy commit」で再デプロイし、SUCCESS と本番URLの HTTP 200 を確認した。

## 次どう防ぐか

| # | 対策 | 状態 |
|---|---|---|
| 1 | 「Wait for CI」をオフにする（循環を断つ） | 実施済み |
| 2 | CI が失敗してもデプロイは止まらなくなったため、**CI が通ってからマージする運用**で補う | 運用ルール |
| 3 | `incident-runbook.md` の「`checkSuites` ゲートで自動反映」の記述を修正する | 実施済み |
| 4 | 次のマージで `Verify Railway Deploy` が SUCCESS になるか確認する | **確認済み**（2026-10-06、PR #34 のマージ時。本番は `WAITING` を挟まず約40秒で SUCCESS、verify も success） |
| 5 | verify が `WAITING` を長く検知したら「本番がスキップされた可能性」を明示して失敗させる、など判定の見直し | 未実施（検討） |

## 学び

監視（verify）とデプロイのゲート（Wait for CI）は、別々に見れば正しい仕組みだった。
**「完了を待つ側」と「完了を待たれる側」を同じコミットのチェックに載せると、循環が起きる。**
新しい自動化を足すときは、既存のゲートが何を待っているかを先に確認する。
