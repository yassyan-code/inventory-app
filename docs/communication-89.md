## ① 専門用語を翻訳する

### 用語の翻訳表

| 専門用語 | 店主に言う言葉 | たとえ |
|---|---|---|
| クラウド(Supabase) | 店のパソコンではなく、ネット上の金庫にデータをしまう | 帳簿を、店の棚でなく銀行の貸金庫に置く。店のパソコンが壊れても、帳簿は無事 |
| データベース | 商品と数を書き込む、ネット上の台帳 | 紙の在庫台帳。1行に1商品 |
| サーバー | ネットの向こうにあって、注文を受けて、返事をするコンピュータ | 店の奥の事務所。窓口に来た注文を、奥の事務所の人が受けて処理する |
| API | データの窓口 | 銀行の窓口。決まった書き方で頼むと、返事が返る |
| ログイン(認証) | 店のスタッフだけが入れるようにする鍵 | 店の裏口の鍵。メールとパスワードが鍵 |
| 権限(RLS) | 「誰が何を見られる・書けるか」の決まりを、台帳側で守る仕組み | 台帳の金庫そのものに鍵をかける。アプリの画面が壊れても、鍵は外れない |
| PWA(ホーム画面に追加) | スマホのホーム画面にアイコンを置いて、アプリのように開ける | 店のホームページを、スマホにショートカットで貼る |
| 1Dバーコード(EAN-13など) | 商品に付いている、縦じまのバーコード | レジで読むあの縦じま。四角い模様(二次元コード)は今回は読めない |
| バックアップ | 台帳の控え。壊れたときに戻せる | 毎晩、帳簿のコピーを別の場所にしまっておく |
| デプロイ | 作ったものを、みんなが使える状態にする | 新しい棚を完成させて、売り場に並べる |
| ステージング環境 | 本番と同じ作りの、お試し用の場所 | 開店前の、お客さんのいない売り場で並べ方を試す |
| レート制限 | 短い時間に、同じ依頼を何度も受け付けない。事務所(サーバー)がパンクしないための決まり | 窓口で、1人が何度も割り込めないようにして、奥の事務所が、ほかの人の注文を受けられるようにする |
| 稼働率(SLO) | 「1か月のうち、何割動いているか」の約束 | 店の営業時間のうち、実際に開いている時間の割合 |
| 入出庫履歴 | 「いつ・何が・いくつ増えて減ったか」の記録 | 台帳の変更の跡。消しゴムで消さず、二重線で直した跡が残るイメージ |

**翻訳のコツ**
- 相手の**仕事の道具**にたとえる(帳簿・棚・レジ・鍵・窓口)。IT同士のたとえ(「Excelみたいなもの」)は、避ける
- **何ができるか・何が困らなくなるか**から話す。仕組みは、聞かれたら話す
- 1つの説明に、新しい言葉は**1つだけ**。たとえで言い換えたら、元の言葉は一度だけ添えて終わり

### 技術を翻訳した文(提出用・アプリの仕組みの説明)

> **このアプリは、「ネット上の台帳」と「店のスタッフ用の鍵」でできています。**
> 商品のバーコードをスマホのカメラで読むと、その商品の名前と、いまの在庫数が出ます。数を増やしたり減らしたりすると、**ネット上の台帳(クラウド)** に書き込まれます。台帳はネット上にあるので、店のスタッフ全員が、それぞれのスマホから同じ数を見られます。1人が入荷を書けば、ほかのスタッフにも、すぐ反映されます。
> 台帳に入れるのは、**メールとパスワードで入ったスタッフだけ**です。入れる人は、店主さんが決めます。
> お店のパソコンが壊れたり、スマホをなくしたりしても、台帳はネット上にあるので、**数は無くなりません**。
> ただし、今のところ、入った人は**全員が同じ台帳を見られます**(店ごと・担当ごとには分けていません)。また、「減ったら知らせる」機能は、今回は入っていません。

(根拠: `docs/spec.md` 2〜3章・5章、`docs/contract-scope-82.md`。「全員が同じ台帳」「通知なし」は、仕様書の未対応と同じ。)

## ② 曖昧を詰める質問5つ

依頼の例: 「**在庫一覧を、いい感じにしてほしい**」

| # | 質問 | ねらい | 聞き方の工夫 |
|---|---|---|---|
| 1 | 「在庫一覧を見るのは、**誰が・いつ・どんな場面**ですか?(例: 朝の開店前に店主さんが / 売り場でスタッフが)」 | 使う場面が分かると、「いい感じ」の中身が決まる | 場面を例で出し、選んでもらう |
| 2 | 「いま見ていて、**困った・イラッとした**のは、どんなときでしたか? 最近の1回を教えてください」 | 「いい感じ」の逆(悪いところ)の方が、具体的に出る | 一般論でなく、**最近の1回の出来事**を聞く |
| 3 | 「『いい感じ』になったら、**何がどう変わって**いますか? 例えば、見つけるのが速い/足りない商品がすぐ分かる/見た目がすっきり、のどれに近いですか」 | 完成の姿(受け入れの基準)を言葉にする | 選択肢を3つ出し、「どれ・全部・別」と聞く |
| 4 | 「**他のアプリ・紙の台帳・他のお店**で、『これは見やすい』と思ったものはありますか? 写真でも構いません」 | 言葉にできない好みを、見本から掴む | 見本を持ってきてもらう |
| 5 | 「全部は同時にできないとき、**一番先に直したい1つ**は何ですか?また、『これはやらなくていい』ものはありますか?」 | 優先順位と、やらないものを決める(範囲の線引き。第82・84課題につながる) | 「全部」と言われたら、「1つだけ選ぶなら」と聞き直す |

**聞いたあとにすること:** 返事を、「〇〇ということで合っていますか?」と**自分の言葉で言い直して確認**する。言い直した文を、そのまま要望(Issue・仕様)に書く。

## ③ 裏の目的を掴む

### 考え方

「言われたこと」は**手段**で、その裏に**目的**がある。手段のまま作ると、作ったのに「そうじゃない」と言われる。

| 言われたこと(手段) | 裏にありそうな目的 | 目的が分かると変わること |
|---|---|---|
| 「在庫一覧に、色を付けてほしい」 | 欠品・発注し忘れを防ぎたい | 色より、「足りなくなったら知らせる」機能(第87課題のT3・T4)が答えかもしれない |
| 「履歴を見られるようにして」 | 数が合わないときの原因を探したい | 一覧より、「その商品の最近の動き」を1画面で見られる方が効く |
| 「CSVで出したい」 | 経理や取引先に渡す資料を作りたい | 出力の形(列・文字コード)を、渡す相手に合わせる |

### 掘り下げる聞き方(5つ)

1. **「それができたら、何が楽になりますか?」** — 手段の先の結果を聞く
2. **「最近、それが無くて困った場面を教えてください」** — 具体的な出来事から目的を引き出す
3. **「それは、何のために必要ですか?」(1〜2回まで)** — 「なぜ」は責める口調になりやすい。「〜のためですか?」と仮説で聞く
4. **「いまは、どうやっていますか?」** — 今のやり方に、困りごとの本体が出る
5. **「もし、それが無かったら、どうなりますか?」** — 本当に必要か、優先度はどのくらいかが分かる

### 想定の会話(例)

> **店主:** 在庫一覧に、色を付けてほしいんです。
> **私:** 色ですね。ちなみに、色が付いたら、どんなときに助かりますか?(質問1)
> **店主:** 足りなくなった商品が、すぐ分かると。
> **私:** 足りなくなったのに気づかなかった、ということが、最近ありましたか?(質問2)
> **店主:** 先月、人気の商品を切らして、お客さんに断ったんです。
> **私:** それは困りましたね。いまは、足りない商品は、どうやって確認していますか?(質問4)
> **店主:** 閉店後に、棚を見て回って。でも、見落とします。
> **私:** 分かりました。「足りなくなる前に、気づけるようにしたい」ということで合っていますか?(言い直して確認)
> **店主:** そう、それです。
> **私(整理):** 色は、そのための1つの方法です。ほかに、「下限を下回ったら一覧で目立たせる」「下限を下回ったら通知する」も考えられます。まず一覧の色から始めて、様子を見る、でいかがですか?

**この会話のポイント:** 「色」を断っていない。目的(欠品を防ぐ)を確かめたうえで、**手段を選び直す選択肢**を出し、決めるのは店主に任せた。
