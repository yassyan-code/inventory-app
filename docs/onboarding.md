# 初めての方へ：最初の1歩（オンボーディング手順・第70課題）

作成日: 2026-10-21

## ゴール（約30分）

自分のPCでアプリを開き、ログインして、商品を1件登録する。
ここまでできれば「最初の1歩」は成功。コードを直すのは、そのあとでよい。

## 用意するもの

- Node.js 22以上（作者は24で確認）。`node --version` で確認する
- Git
- メールアドレス（Supabaseの確認メールを受け取る）
- Supabaseの無料アカウント（手順3で作る）

## 手順

### 1. ソースを取ってくる

```bash
git clone https://github.com/yassyan-code/inventory-app.git
cd inventory-app
```

- できた合図: `README.md` と `package.json` がある
- 詰まったら: `git` が無いと言われたらGitを入れる。フォルダを間違えていないか `ls` で見る

### 2. 部品を入れる

```bash
npm install
```

- できた合図: `added ○○ packages` と出て、プロンプトに戻る
- 先回り: **1分ほどかかる**。止まったように見えても待つ。`deprecated` の警告は無視してよい

### 3. 自分用のデータ置き場（Supabase）を作る

1. https://supabase.com で無料アカウントを作り、新しいプロジェクトを作る
2. 左メニュー「SQL Editor」に `supabase/schema.sql` の中身を貼り付けて実行する
3. 「Project Settings → API」の **Project URL** と **anon public key** をメモする

- できた合図: 「Table Editor」に `products` や `teams` が見える
- 先回り: プロジェクト作成は数分かかる。鍵は2つ（URLとanon key）。**service_role key は使わない・貼らない**

### 4. 設定ファイルを作る

```bash
cp .env.example .env
```

`.env` を開き、`VITE_SUPABASE_URL` と `VITE_SUPABASE_ANON_KEY` にメモした値を入れる。

- できた合図: `.env` に2つの値が入っている
- 先回り: `.env` は git に載らない（公開されない）。値の前後に空白や引用符を付けない

### 5. 起動する

```bash
npm run dev
```

表示されたURL（例: `http://localhost:5173`）をブラウザで開く。

- できた合図: ログイン画面が見える
- 詰まったら: 画面が真っ白なら、ブラウザの開発者ツール(F12)のConsoleを見る。`VITE_SUPABASE_URL ... が設定されていません` が出たら手順4へ戻る。`.env` を直したら `npm run dev` を一度止めて起動し直す

### 6. アカウントを作って、商品を1件登録する

1. メールとパスワードでアカウントを作る
2. Supabaseから確認メールが届くので、リンクを開いてからログインする
3. 「スキャン登録」タブで、バーコードの欄に `1234567890` と入力して登録する（商品名は好きな名前でよい）

- できた合図: 「在庫一覧」タブに、登録した商品が出る
- 先回り: 確認メールは**迷惑メールに入ることがある**。届かないときは迷惑メールを見る

### 7. 動作確認（任意）

```bash
npm test
```

- できた合図: `Tests ... passed` と出る（作者の環境では60件）
- 先回り: `npm run lint` の警告が1件出るが、動作には関係ない

## 試した結果（ドライラン）

**実施日: 2026-10-21。** 新しい空のフォルダにGitHubから取り直し、手順どおりになぞった。
実際の初心者に試してもらったわけではない。ブラウザ操作と自分のSupabaseでの登録（手順3・5・6）は、まだ試していない。
動かしたのは、手順1・2・4・7とビルドで、手順書に反映した。

見つかった詰まり所と直し方:

1. **`.env.example` が存在しなかった**（手順4で `cp: cannot stat '.env.example'`）
   - 原因: ファイルが未マージの別ブランチにしかなく、さらに `.gitignore` の `.env*` がこのファイルも無視していた
   - 直し: `.env.example` を追加し、`.gitignore` の重複行 `.env*` を削除した
2. **`npm install` が約80秒かかる**
   - 止まったと思って中断しやすい → READMEと手順2に「1分ほどかかる」と明記した
3. **`schema.sql` は基本部分だけ**（`error_logs`・監査ログなどは含まれない）
   - READMEは「これを貼ればよい」と読める → 007〜013を別途実行する旨をREADMEに追記した
4. 手順の最後（`npm test` 60件・`npm run build`）は問題なし。lint警告1件は無害

未対応（次の改善候補）:

- READMEの冒頭に、過去の確認用メモ（「GitHub連携による自動デプロイ確認用の変更です」）が残っていて、初心者には意味が分からない
- 実際の初心者に手順3〜6を試してもらい、確認メールの届き方や画面の迷いを記録する
