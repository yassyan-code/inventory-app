# 見積りの実務(第84課題・想定案件)

> **これは練習用の想定案件です。** 金額・時間・単価はすべて例で、実在の取引ではありません。
> 案件は第82課題(`docs/contract-scope-82.md`)と同じ。スコープ表の「やる」5項目だけを見積もります。

## ① 作業に分けて積む(工数)

| # | 作業 | 時間 | 根拠 |
|---|---|---|---|
| 1 | 要件確認・仕様書の合意 | 4h | 店主とのヒアリング1回+仕様書の見直し |
| 2 | 環境構築(DB設計・アクセス制御・本番の器) | 8h | 実績あり。ただし依頼者名義で作り直す手間を含む |
| 3 | ログイン・スタッフ分のアカウント発行 | 6h | 認証は実装済みの流用。発行手順と確認が中心 |
| 4 | バーコードでの商品登録 | 14h | スマホ実機(機種・光の具合)での調整が読めない |
| 5 | 入出庫の記録 | 8h | 仕様は単純。同時操作の確認を含む |
| 6 | 在庫一覧・検索 | 8h | 実装済みの流用+店の商品数での速度確認 |
| 7 | テスト(実機・複数端末) | 8h | スタッフのスマホ2〜3機種を想定 |
| 8 | 本番設置・操作説明の資料と説明30分 | 6h | 資料づくり3h+設置2h+説明1h |
| 9 | 検収対応(7日間)・指摘の修正 | 4h | 軽微な直しのみ |
| 10 | 連絡・打合せ(4週間分) | 6h | 週1回の進捗連絡+質問対応 |
| | **積み上げ合計** | **72h** | |

## ② バッファと金額

**時間単価(逆算):** 月30万円ほしい ÷ 請求できる時間 月100時間 = **3,000円/時**
(月の実働の約6割。残りは営業・事務・勉強・請求書づくりに使うため)

**バッファ:** 積み上げ72h × **30%** = 約22h を上乗せ
- 想定外は必ず起きる。特に#4(実機)と、依頼者の確認待ちで止まる時間
- 削る方向の交渉が来ても、ここは削らない(削るなら範囲を減らす)

| 項目 | 計算 | 金額 |
|---|---|---|
| 積み上げ | 72h × 3,000円 | 216,000円 |
| バッファ(30%) | 22h × 3,000円 | 66,000円 |
| **提示金額(一式)** | 約94h | **約28万円(税別)** |

- 外部サービスの利用料(Supabase・ホスティング)は含まない
- 支払い: 着手時 14万円・検収後 14万円
- 納品後30日の不具合修正は、バッファの範囲で対応する

## ③ 交渉に備える(角の立たない返し方)

| 場面 | 返し方(例) |
|---|---|
| 「高い」と言われた | 「内訳は〇〇の積み上げです。ご予算に合わせるなら、金額ではなく範囲を調整します。たとえば検索機能を後回しにすれば、約△万円下げられます」 |
| 「もっと負けて」 | 「時間単価と余裕は崩せません。代わりに、依頼者側で用意いただける作業(商品名の一覧づくりなど)があれば、その分を引けます」 |
| 後から要望が増えた | 「ありがとうございます、できます。ただ今回の範囲には入っていないので、内容・金額・納期をお出しします。合意いただいてから着手します」 |
| 「ちょっとだけだから」 | 「小さいものは〇時間で、〇円です。お見積りをメールでお送りしますね」(小さくても口約束で受けない) |
| 急ぎにしてほしい | 「前倒しは、他の予定を動かすので〇割増になります。通常納期なら〇日です」 |

## この見積りで、まだ分からないこと

- 単価3,000円は逆算した例。相場や自分の実績とは照らし合わせていない
- 工数は想定。実際にかかった時間を記録して、次回の見積りと比べるまでは当たっているか不明
